# PuttPhysics 開発状況・引継ぎメモ

最終更新: 2026-08-17

## 1. この文書の位置づけ

この文書は、PuttPhysics の現時点での開発状況、設計方針、検証結果、次回作業を引き継ぐためのメモである。

**確定仕様書ではない。**

開発・実機検証の結果によって、ここに記載した方針や仕様は今後変更される可能性がある。

Git のソースコードを正式な実装状態とし、この文書は「なぜその実装になっているか」「現在どの方向を目指しているか」「次に何をするか」を補足するために使用する。

## 2. PuttPhysics の目的

ゴルフのパッティング動画を解析し、パッティング動作およびボール挙動を数値化して、練習・診断に利用できるアプリを開発する。

主な分析・診断候補:

- インパクト付近のパターヘッド速度
- ボールの移動・速度
- 方向
- パッティングのタイミング
- 将来的なミート率（打点・芯）の評価
- 将来的な傾斜・グリーンスピード等との統合
- 蓄積データからのミス原因分析

物理モデルは現時点では「総合振り子」の考え方を基本とする。

検証項目:

**現在横から撮影していることは、完成版も横撮影にするという意味ではない。**

### 4.2 現時点の最終系イメージ

現時点では、最終的な基本撮影は**ボール後方側からの撮影**を想定している。

シートは上から見たときに**右側が縦棒になる、逆向きの「コ」の字型**を想定する。

ボールは**右から左へ転がる**。

カメラは**「コ」の字の右側の縦棒より、さらに右側**に配置する構想である。

概念図（上から見たイメージ）:

```text

   ─────────────────┐
                    │
                    │

                         （縦棒の右側）

      右側が縦棒になる
      逆向きの「コ」の字型シート
```

これは**現時点の最終系構想であり、確定仕様ではない**。シート形状・寸法、ボール位置、カメラ位置・距離・高さ・角度、撮影方向そのものは今後変更される可能性がある。

## 6. 現在のボール検出方式

現在は主として色を利用してボールを検出している。対象色は赤・黄。

基本処理:

1. 動画からフレーム画像を取得
2. 色判定
3. ColorMask 作成
4. Blob 抽出
5. BlobFilter による候補選別
6. BallCandidate 作成
7. BallTracker によるフレーム間追跡

主な関連ファイル:

- `lib/services/color_detector.dart`
- `lib/services/color_scanner.dart`
- `lib/services/blob_analyzer.dart`
- `lib/services/blob_filter.dart`
- `lib/services/image_inspector.dart`
- `lib/services/ball_tracker.dart`
- `lib/models/ball_candidate.dart`
- `lib/models/tracked_ball.dart`
- `lib/models/tracking_session.dart`

## 7. Blob / BallCandidate

BlobFilterでは、ピクセル数、幅・高さ、縦横比、fill
ratioなどを利用して候補を判定する。

BallCandidateには通常候補に加えて `isCombinedRedYellow` と
`isMotionBlur` を持たせている。

赤領域と黄領域が近接し全体としてボールらしい場合はCombined
Red/Yellow候補を生成する。

インパクト直後の高速移動で円形ではなく横方向に伸びたBlobとなる場合はmotion
blur候補として扱う。

## 8. BallTracker の現在の考え方

候補選択では以下を考慮する:

- 前フレームからの移動距離
- 半径変化
- confidence
- 過去2点からの移動予測
- motion blur
- combined red/yellow
- ボール移動開始判定
- 高速移動後の進行方向
- 同方向への移動継続

## 9. 高速追跡で判明した問題

### 9.1 古い位置のBlobを再採用する問題

例:

```text
frame 73   x=612.5
frame 74   x=506.5
frame 75   x=506.5
frame 76   x=506.5
frame 77   x=365.5
```

実際のボールが左へ進んでいるにもかかわらず、直前位置に残った高confidenceのBlobを再採用すると、その後の本物らしい候補までの距離が大きくなり追跡が切れる。

### 9.2 通常移動上限120pxを超える問題

実機例:

```text
594.5
→ 533.0
→ 386.5
```

最後の移動は約146.6px。従来は通常候補の120px上限を超えるため拒否された。

## 10. 直近で追加した追跡改善

### 10.1 移動予測

過去2点から速度を計算し次フレームの予測位置を算出する。診断ログにはprevious/last
position、velocity、predicted position、candidate position、prediction
error、prediction scoreを出す。

### 10.2 高速移動後の進行方向優先

十分大きな移動の後は、直前位置に残った候補より予測された進行方向へ進む候補を優先する。静止時・低速時には強制しない。

### 10.3 同方向移動時の移動上限拡張

ボールがすでに移動開始し、候補が直前の移動方向と一致する場合は通常の120pxより大きな移動を許可する。現時点の拡張上限は**160px**。無制限に遠い候補を採用するものではない。
