# PuttPhysics 動画解析高速化・誤追跡防止 設計メモ

作成日：2026-11-08  
対象：`feature/native-analysis-speedup`（確認時のコミット `5162f5d`）  
状態：**設計方針の整理。以下の改善は未実装。**

## 1. 目的

- 動画解析時間を短縮する。
- パターヘッドのインパクト付近の速度測定と、ボールの転がり速度測定の精度を維持する。
- 予測範囲外の色領域などへボール追跡が飛び移る誤検出を防ぐ。

## 2. 現在の実装（コード確認済み）

- `lib/screens/camera_screen.dart` は、動画の各フレームで `PutterDetector.detectDecoded()` と `BallTracker.track()` を実行している。ボール移動後もパター検出が続く。
- `lib/services/putter_detector.dart` は画像の全ピクセルを走査してピンク色を抽出する。初期ボール位置を基準としたROI制限はない。
- ボール側の `ImageInspector.inspectDecoded()` は動的ROIを利用するが、現在の余白は `400 + missedFrames × 150` ピクセルであり、未検出時に拡大する。
- `BallTracker` は位置予測、移動距離、方向、候補サイズ、信頼度などで候補を選択する。マーカーを結ぶ左右の境界線や、初期ボール位置より奥側という幾何学的制約は追跡候補に適用されていない。
- マーカー4点は、保存済みの手動確定位置があれば初回フレームのキャリブレーションに利用される。
- 上側2点のマーカーを結ぶラインの通過を条件に動画解析を終了する処理は、確認した `camera_screen.dart` の自動解析ループにはない。
- Swift由来のネイティブフレーム番号を自動追跡に渡す修正は実施済み。ただし実機での一致確認は未実施。

## 3. 採用する解析方針

### 3.1 ボールが動く前（インパクト前）

- **パターヘッド**：初期設定したボール位置より手前側を中心に、必要な範囲だけ検出・追跡する。
- **ボール**：初期位置近傍だけを監視し、移動開始を判定する。
- インパクト速度の測定に必要なフレームを取り逃がさないよう、パター検出停止のタイミングはボール移動開始の判定と整合させる。

### 3.2 ボールが動き始めた後

- **パターヘッド**：インパクト付近の必要な追跡データを確保した後、検出処理を停止する。
- **ボール**：直前の位置、速度、実際のPTS（フレーム時刻）から予測した近傍のROIのみを画像走査する。
- ボールの初期位置より奥側を探索対象とする。画像座標の上下方向は、実際のマーカー配置と座標系に基づき定義する。
- 左右のマーカー境界は、予測ROIが十分狭ければ毎フレームの画像走査範囲として必須ではない。ただし候補の妥当性を検証する幾何学的制約として利用するかは検討する。
- **予測範囲内で見つからなければ未検出とし、探索範囲を無制限に広げたり、別の候補へ飛び移ったりしない。**
- 移動開始直後は速度推定が不安定なため、初期数フレームの許容幅を別途設計する。

### 3.3 解析終了

- ボールが上側2点のマーカーを結ぶラインを通過したら、フレーム解析を終了する。
- ラインの傾きを考慮した判定とし、単純な固定Y座標では判定しない。
- 一時的な未検出とライン通過を混同しない。
- 移動開始後に**4フレーム連続未検出**の場合は測定を終了する案を検討する（現時点では設計案であり、実装確定ではない）。

## 4. 性能改善の優先順位

1. **ボール移動後のパターヘッド検出停止**：現在の全画面ピンク色走査を省略。
2. **インパクト前のパターヘッドROI制限**：必要な手前側のみ走査。
3. **ボールの予測ROI縮小と再探索抑止**：色判定・Blob解析の対象画素を削減し、誤追跡を防止。
4. **上側マーカー通過で動画解析終了**：残りのフレームのデコード・解析を省略。

## 5. 実装時の注意

- ROIを呼び出し側で指定するだけでは `PutterDetector` は速くならない。`detectDecoded()` 内部の画素走査範囲を変更する必要がある。
- **画像走査ROI**と**追跡候補の採否判定**は分離する。ROI縮小は高速化、候補制限は誤検出防止が主目的。
- `BallTracker` の既存の速度・方向・半径・信頼度評価は維持し、予測範囲外の候補を採用しない条件を追加する。
- インパクト速度を求めるため、パター検出を早く止めすぎない。必要なら停止判定までの少数フレームを保持する。
- `FrameExtractor` のネイティブPTSと0始まりフレーム番号を継続利用する。
- 変更は一度にまとめず、各段階で追跡精度と処理時間を比較する。

## 6. 検証方法

- 変更前の `IMAGE DECODE TIMING`、`PUTTER DETECT TIMING`、`IMAGE INSPECT` 関連時間、総解析時間を基準値として記録する。
- 同一の120fps動画を使い、各変更後の総解析時間、処理フレーム数、検出・追跡成功数を比較する。
- インパクト付近のパターヘッド速度、ボール初速、未検出・誤追跡を確認する。
- `flutter analyze` と `flutter test` を通し、iPhone実機で動作確認する。
- ROIの画素数が90%減っても、動画全体の処理時間が90%減るとは限らない。実際の改善率は計測する。
